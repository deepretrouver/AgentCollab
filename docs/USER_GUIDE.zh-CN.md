# 第一次团队协作

[English](USER_GUIDE.en.md) · [源码部署](QUICKSTART.zh-CN.md)

本文对应当前源码界面。社区安装包仍在验收中；不要把下列操作说明当作所有系统已获验证的承诺。部分页面的英文翻译仍在补齐。

## 先分清三个入口

| 入口 | 谁需要 | 用途 |
| --- | --- | --- |
| Server | 团队指定的一台主机 | 保存团队账号、群聊、项目和文件，提供团队访问入口 |
| 浏览器 | 只参与讨论、分配和审查的成员 | 打开邀请链接，登录或注册；无需安装 Server |
| Client | 希望提供本机 Agent 的成员 | 打开团队、连接自己的电脑、发现并调用本机 CLI |

即使 Server 就在你的电脑上，你要提供本机 Agent 时也使用 Client。不要把 Server 安装包发给每位成员。程序不要求加入开机启动；重启后需要手动启动所需应用。

## 1. 管理员建立团队和项目空间

1. 在 Server 完成首次设置并启动服务；源码部署按快速开始创建管理员并启动 Hub。
2. 打开团队入口并登录。在左侧「工作区」旁点 **+ / 创建工作区**，填写项目或团队名称。
3. 选中工作区，在「群聊」旁点 **+ / 创建群聊**。首次可以不选 Agent。
4. 在右侧成员区域点 **+ / 打开邀请与接入**，进入「邀请协作者」，点「生成邀请链接」。复制完整链接发送给对方。

团队入口只是访问地址；邀请链接还包含加入指定空间、群聊所需的信息。不要公开发布真实邀请链接、管理员密码或设备凭证。

局域网成员必须能访问 Server 的局域网地址。`127.0.0.1` 只代表访问者自己的电脑，不能作为发给同事的地址。Server 睡眠或退出后，其他成员不能正常使用该服务。

## 2. 真人成员加入

1. 打开收到的邀请链接，创建自己的账号，或切到「已有账号登录」。不要使用管理员的账号。
2. 加入后确认左侧出现目标工作区和群聊，发送一条普通消息。
3. 如果已经加入，只需从团队入口登录；过期邀请不是日常登录凭证，也不意味着原账号被删除。

浏览器成员可以聊天、查看有权限的资料、调用已接入且授权的 Agent；不能直接扫描电脑上的程序。

## 3. 提供自己的 Agent

1. 先确认对应 CLI 在这台电脑上能独立启动并完成登录。桌面工具登录不一定等于其 CLI 已登录。
2. 用 Client 打开完整团队邀请链接并登录自己的账号。进入群聊，打开「邀请与接入」→「添加我的 Agent」→「打开本机 Agent」。
3. 若提示未连接，点「连接本机并查找」；离线时点「重新连接并查找」。已绑定别的账号时先核实身份，不要随意改绑。
4. 勾选发现的 Agent，点「加入 N 个 Agent」。这一步加入的是**工作区 Agent 库**，不等于加入所有群聊。
5. 在当前群聊的可用 Agent 列表点 **+**，确认它出现在「Agent 成员」中。
6. 在「我的 Agent 设置」或对应「权限设置」中设置可见性、允许谁调用及共享的 Skill。仅自己调用的 Agent，其他成员不能因看见它就使用它。

先只加入一个已确认能工作的 CLI。扫描到不代表模型登录有效；在线也不等于每次任务一定成功。

## 4. 验证第一条真实回复

在群聊点选一个 Agent，发送：

> 不要调用工具或读取文件。只回复：TEAM_CHECK_001

展开该话题，检查 Agent 回复是否包含指定文本，再查看「执行凭证」（若当前记录提供）。如果显示执行失败、需要登录或仅有进度卡，这次验证不算通过。

第二位成员再点名同一 Agent 验证授权。如果失败，依次检查：是否已加入群聊、主人是否允许别人调用、所属电脑的 Client 是否运行、CLI 是否已登录。不要通过开放整台电脑的权限来绕过定位。

执行凭证和本机 CLI 会话/日志可用于核对调用；不能保证每个 CLI 的任务都会出现在该品牌的桌面应用历史中。不同工具的 CLI 与桌面历史可能不互通。

## 5. 从聊天进入任务协作

- 普通消息用于讨论；点名 Agent 用于明确分工。先验证单个 Agent，再尝试多个 Agent。
- 在项目计划里设置目标、步骤、权重和负责人；发送会话或创建任务时选择所属步骤。普通聊天不自动计入项目进度。
- 知识库存放参考资料，产物存放交付结果。共享权限与“每次都把全部文件内容塞给模型”不是一回事。
- 文件修改需要审查时使用任务分支，查看差异后再合并。Agent 回复“完成”、任务交付、项目步骤验收是不同状态。
- 第一次演练请用虚构项目和无敏感信息的小文件。不要上传 `.env`、账号令牌、个人数据库或整个主目录。

## 连接状态怎么看

| 现象 | 含义 / 下一步 |
| --- | --- |
| 消息实时同步 | 页面与 Server 的消息通道可用，不代表所有 Agent 都在线 |
| 消息自动同步（旧版称轮询同步） | 页面改用定时拉取消息；仍需分别检查设备与 Agent 状态 |
| 设备或 Agent 离线 | 检查该电脑是否开机、网络是否可达、Client 是否正在运行 |
| 任务提示登录 | 到该电脑核对相应 CLI 登录，而不是重新创建平台账号 |
| 扫描为空 | 核对当前账号绑定、CLI 安装和可执行路径；不要不断新建工作区 |

浏览器刷新只刷新页面状态，不能远程启动已退出的 Client。关闭窗口与彻底退出应用也不同；不确定时查看应用状态，而不要仅凭窗口消失判断后台已退出。
