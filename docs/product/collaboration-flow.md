# AgentCollab 统一协作流程

AgentCollab 不把多 Agent 会话、真人邀请、本机接入和 Git 编排做成四套互不相干的产品。对使用者只保留一条主流程：

1. **邀请加入**：群主或管理员从“邀请与接入”生成一个链接。对方打开后登录或创建自己的真人账号，直接进入目标工作区和群聊。只参与讨论、查看计划或验收成果的人不需要安装 Client。
2. **贡献本机能力（可选）**：成员希望把自己电脑上的 Agent、Skills 和授权资源加入团队时，才选择“添加我的 Agent”。桌面 Client 负责绑定当前账号、发现本机 CLI、保持连接和执行任务；设备配对码是这一可选步骤的内部凭证，不是日常邀请真人的入口。
3. **共享话题上下文**：每条真人发言可以成为一个折叠话题。被点名的多个 Agent 读取同一条根消息、同一群聊上下文、附件和知识库，回复回到原话题；内部调度提示不替换真人原文。
4. **纳入项目计划（可选）**：发起会话时选择项目步骤，该话题才成为看板事项并影响计划流程。普通聊天不计进度。每个步骤可以指定真人和 Agent 负责人、权重与验收状态。
5. **共享可读、更新受控**：群成员和群内 Agent 默认可读公共底稿、知识库和产物；聊天任务取得公共底稿的临时副本，不能直接覆盖 Server。只有项目管理员或步骤负责人可以更新公共底稿。询问“做到哪里”时再点名负责人的 Agent，读取这台电脑里的最新现场。
6. **文件工作与 Git 分支（按需）**：只有负责人明确提交目录审查时，Server 才为该事项建立独立分支。同一话题内可持续更新提交，不要求用户先学习 Git 命令，也不会把一次进度汇报误当成交付。
7. **审查与合并**：事项进入待验收后，在原话题或看板点击“查看改动”。界面列出分支、文件清单、增删行数和冲突状态；确认后才合并到工作区受保护主分支并更新项目状态。

## 四类参考能力如何落在本项目

- **Herdr 式协作**：同一话题中的多 Agent 共享任务上下文、相互协作，且各自保持真实 CLI 身份和原生会话。
- **Orca 式编排**：项目步骤、事项分支、文件 Diff、冲突检查、人工审查和主分支合并形成闭环。
- **ClawChat / QM 式接入**：真人首先用一个链接加入；Client 安装和本机 Agent 接入是登录后的可选路径，不向普通协作者暴露 Hub 地址、Runner 邀请等实现名词。
- **AgentCollab 自身边界**：每个 Agent 始终归其真人所有者；主人决定可见范围、谁能调用和共享哪些 Skills。群管理员能治理群成员和任务，但不能替主人扩大 Agent 的本机权限。

## 用户只需认识的对象

| 对象 | 用户理解 | 系统职责 |
| --- | --- | --- |
| 工作区 | 一个长期团队或大项目 | 成员、总计划、知识库和 Git 主仓的边界 |
| 群聊 | 一个协作频道或项目环节 | 共享时间线、成员、Agent 和本群资料 |
| 话题 | 一次具体问题、任务或决策 | 汇总真人原文、Agent 执行、交付与文件分支 |
| 项目步骤 | 计划中的可验收环节 | 负责人、权重、主工作区和总体进度 |
| Client | 我贡献本机 Agent 时使用的桌面能力 | 发现 CLI、保持连接、执行和回传凭证 |

因此，正常真人加入不再需要理解“Hub 地址 + 真人邀请码 + Runner 配对码”。群管理员发一个链接即可；对方只有在主动贡献自己的本机 Agent 时，才进入 Client 接入流程。
