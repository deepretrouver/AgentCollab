# AgentCollab 操作参考

原始版本：2026-08-14 / 1.3.1；社区预览边界修订：2026-10-30。

适用范围：可信小团队协作；历史细节仍在逐项核对。

> 首次使用请先看[中文首次协作指南](USER_GUIDE.zh-CN.md)或[English guide](USER_GUIDE.en.md)。本文保留较详细的操作参考，不作为全部功能或平台已通过验收的证明。当前证据见[发布验收状态](ops/open-source-readiness.md)和[Agent 验证矩阵](agents/compatibility.md)。旧 Runner 脚本、手工设备码和一体程序不是桌面版常规流程。

## 1. 先用一分钟理解整套系统

AgentCollab 由两个程序组成：

- **AgentCollab Server**：团队服务器，只在一台固定电脑上安装。保存账号、工作区、群聊、消息、项目计划、共享文件、Git 正式版本和审计记录。
- **AgentCollab Client**：需要接入本机 Agent 的成员安装，包括要贡献本机 Agent 的 Server 管理员。只参与聊天和审查的真人可使用浏览器，不必安装 Client。

正常使用只需记住三条路径：

1. 管理员打开 Server，建立团队。
2. 群主发送一个“邀请真人”链接，对方登录或注册后直接入群。
3. 想贡献本机 Agent 的成员，在自己的 Client 点击“添加我的 Agent”。只参加真人讨论的人可以不安装 Client，直接用浏览器加入。

不要把以下概念混在一起：

| 对象 | 通俗理解 | 保存在哪里 |
| --- | --- | --- |
| 工作区 | 一个完整项目或团队范围 | Server |
| 群聊 | 项目中的协作频道 | Server |
| 话题会话 | 一条真人问题及其 Agent 回复串 | Server |
| 项目步骤 | 计划中的阶段或子任务 | Server |
| 负责人本机目录 | 某人在自己电脑持续工作的现场 | 该成员 Client 所在电脑 |
| 团队正式版 | 已提交、审查并合并的统一版本 | Server 的 Git 主仓 |
| 知识库 | 规范、历史资料、参考样例 | Server 共享目录 |
| 产物 | Agent 交付、待验收文件和阶段结果 | Server |

## 2. 当前安装包与启动方式

macOS 安装包通过验收后，建议把应用放入 `/Applications`，从固定位置启动：

- `/Applications/AgentCollab Server.app`
- `/Applications/AgentCollab.app`

仓库里的 `release/`、历史归档和废纸篓副本是构建或留档文件，不要从 Spotlight 或 Finder 打开它们。

核对应用显示的版本与所下载的发布说明一致；不要按本文旧版本号寻找历史安装包。

### 每天如何启动

- Server 主机：打开 **AgentCollab Server**；需要贡献本机 Agent 时再打开 **AgentCollab Client**。
- 普通成员：只打开 **AgentCollab Client**。
- 只用浏览器聊天的成员：打开团队或群聊邀请链接即可。

本版本按要求**不会加入开机登录项**。电脑重启后需要手动打开应用。关闭窗口可能只是缩到菜单栏并继续运行；要彻底停止，请从菜单栏图标选择“退出”。

### 当前平台发布范围

- macOS Apple 芯片版已有本地封装与部分验收证据；最终安装包仍须与当前源码版本核对。
- 下载中心存在某个包不等于该系统已通过测试；以对应发布说明列出的验收平台为准。
- 不要把旧 `/downloads/runner` 兼容包当作普通成员的正式图形 Client。

## 3. 管理员首次建立团队

只在 Server 主机执行一次：

1. 打开 **AgentCollab Server**。
2. 填写协作中心名称。
3. 网络选择优先用“自动地址”；若单位提供固定 IP 或 DNS，可改用固定地址。
4. 选择 Server 数据目录。账号、消息、附件、知识库和 Git 主仓都以这里为权威数据。
5. 为固定用户名 `owner` 设置密码。密码只要求非空；用户名支持中文、英文、数字和常用符号，最长 64 个字符。
6. 启动 Server，确认状态为正常。
7. 点击“进入团队”，再用 Client 以 `owner` 登录。

同一台 Server 只保留一个权威数据目录。不要同时启动旧版 Hub、一体版或第二个 Server，否则可能造成端口冲突和 Agent 心跳归错服务。

## 4. 账号和权限

权限分为三层，互不自动继承。

### 4.1 Hub 平台角色

- **默认 Hub 管理员**：固定账号 `owner`，不可降级或删除。
- **Hub 管理员**：管理平台注册账号、提升或撤销其他 Hub 管理员、清理测试账号。
- **普通账号**：没有平台级账号管理权限。

Hub 管理员不会因为这个身份自动进入或查看所有工作区和群聊。

操作路径：左下角个人资料 → **管理 Hub 账号权限**。

Hub 管理员可在这里删除不再使用的普通账号或测试账号。删除后账号不能再登录并从账号名单隐藏，但历史消息保留原署名；默认 `owner` 不能删除。

### 4.2 工作区角色

- **Owner**：创建工作区的人；可修改、删除工作区，管理工作区成员和项目计划。
- **管理员**：可管理工作区项目与成员，但不能取代 Owner 的所有权。
- **成员**：只能进入自己已加入的工作区并参与获准的协作。

操作路径：左侧工作区右侧的齿轮 → 工作区设置 / 成员管理。

### 4.3 群聊角色

- **群主**：创建群聊的人。
- **管理员**：可邀请、添加或移出本群的真人和 Agent。
- **成员**：参与聊天和已授权任务。

群主或群管理员可以把 Agent 移出群，但不能替 Agent 主人扩大调用范围、共享 Skill 或更改其响应方式。

## 5. 创建、修改和删除工作区与群聊

### 创建工作区

1. 左侧“工作区”标题旁点击 `+`。
2. 填写名称并创建。
3. 创建者自动成为该工作区 Owner。

### 修改或删除工作区

1. 选中工作区。
2. 点击工作区右侧齿轮。
3. 可修改名称，或点击“确认删除”。

删除工作区会删除其中群聊、消息、共享文件、Git 文件和该工作区内的 Agent 记录，无法恢复；但不会删除其他工作区复用的本机 Agent，也不会删除成员电脑上的原目录。若仍有排队或执行中的 Agent 任务，系统会要求先停止或等待任务结束。删除前应备份 Server 数据目录。

### 创建群聊

1. 选中工作区。
2. 在“群聊”标题旁点击 `+`。
3. 输入群名并创建。
4. 群聊建好后，再从右侧“可用 Agent”加入需要的 Agent。

群聊可置顶，并可按时间或名称排序；置顶项不参与普通排序。

### 调整界面布局

- 顶部“视图布局”可隐藏或恢复左侧工作区栏、右侧群详情栏。
- 当前群聊的成员在左侧群聊名称下方作为二级列表显示；点击任一真人姓名，可独立折叠或展开他名下的 Agent。右侧只保留“邀请与接入”“可用 Agent”“高级 · 连接诊断”等常用工具；“可用 Agent”展开后也按所有者分组，点击所有者姓名可独立收起其 Agent。
- 折叠后仍保留“邀请与接入”“添加我的 Agent”“运行检查”等主要快捷入口。

## 6. 邀请真人加入

### 推荐方式：一个邀请链接

1. 进入目标群聊。
2. 右侧点击 **邀请与接入**。
3. 选择 **邀请协作者** / **生成邀请链接**。
4. 点击复制，把唯一链接发给对方。
5. 对方打开链接，选择“创建新账号”或“已有账号登录”。
6. 成功后自动加入对应工作区和群聊。

对方只参加聊天、看板和验收时，可以不安装 Client。只有要连接自己的电脑和 Agent 时才需要 Client。

邀请链接过期或已使用时，由群主或群管理员重新生成。已经存在的真人账号不需要重新创建；对方选择“已有账号登录”即可。

## 7. 安装 Client 并添加自己的 Agent

### 7.1 获取 Client

- 从邀请页点击“下载 Client”或“在 Client 中打开”。
- 也可从 Server 提供的 Client 下载中心获取当前正式版本。
- 安装后用刚才的同一真人账号登录。

Client 会保存团队身份和设备凭证。更新、休眠、暂时离开办公网或普通重启不需要重新填写 Hub 地址和配对码；回到同一局域网后会自动寻找同一个 Server。

### 7.2 添加本机 Agent

1. 在 Client 登录目标团队。
2. 进入任一目标群聊。
3. 右侧点击 **邀请与接入** → **添加我的 Agent**；也可在“可用 Agent”旁点击 `+`。
4. 首次出现“连接本机并查找”时点击它。
5. Client 扫描当前电脑真实可执行且可用的 CLI。
6. 勾选要加入平台的 Agent。
7. 先加入工作区 Agent 库，再选择加入当前群聊。

已在同一 Hub 的其他工作区注册过的本机 Agent可以直接复用，不必重新安装或配对。

### 7.3 当前可发现的 Agent

默认适配目录包括 Hermes、Codex、Pi、WorkBuddy/CodeBuddy、Claude Code、OpenCode、OpenClaw，以及已安装的 ACP 预设或自定义 ACP Agent。实际列表以这台电脑上已安装、已登录并可执行的 CLI 为准。

Server 会发布版本化 Agent 目录，Client 自动更新发现规则。新增沿用已有输出协议的 CLI 通常不需要重装 Client；采用全新通信协议时才需要升级 Client。

### 7.4 扫描不到时

依次检查：

1. 当前打开的是 **AgentCollab Client**，不是纯浏览器页面或 Server 管理窗口。
2. Client 已登录正确账号，并显示本机连接成功。
3. 目标 CLI 已安装，且在终端中可执行。
4. 目标 CLI 已完成自己的登录认证。
5. 点击“重新连接并查找”或右侧“高级 · 连接诊断 → 运行检查”。

## 8. Agent 所有权、调用权限和 Skill

每个 Agent 永远归把它接入平台的真人账号所有。

Agent 主人通过右侧“我的 Agent 设置”入口控制：

- **可见范围**：仅自己可见 / 工作区可见。
- **调用范围**：仅自己调用 / 所在群成员调用。
- **共享 Skills**：其他成员只能看到并使用主人勾选的 Skills。

非主人看到的能力清单会按共享权限过滤，跨所有者任务不会自动注入未授权 Skill。
这不等于所有输出均已脱敏：执行凭证可能包含可执行路径、设备名、原生会话 ID，
Agent 回复也可能引用本机路径。分享会话或提交问题前，须检查正文、附件和凭证。

当前原生 Agent 子进程仍使用其电脑当前登录用户的系统权限。平台授权不是操作系统沙箱；不要向不可信成员开放高权限 Agent 或敏感 Skill。

## 9. 群内四种 Agent 响应方式

在左侧群聊成员中展开自己的 Agent，点击“详情 / 群内设置”。只有 Agent 主人能修改。

| 模式 | 何时响应 | 适合场景 |
| --- | --- | --- |
| 仅被 @ 时 | 明确点名该 Agent 才运行 | 默认、最清晰、最省资源 |
| 主协调 / 自动分诊 | 接收普通真人消息，拆解、点名专家并汇总 | 有固定项目经理 Agent 的群 |
| 回复所有真人消息 | 每条真人消息都响应 | 小型开放讨论，成员和 Agent 较少 |
| 静默 | 不自动参与调度 | 暂时保留但不希望运行 |

一个群只应有一个主协调。响应方式不会绕过调用权限：如果主人没有开放给群成员，其他真人仍不能调用。

## 10. 聊天、点名、任务与专题讨论

### 10.1 普通聊天

直接输入文字发送。只用于真人交流，不会自动变成项目进度，也不会自动触发“仅被 @”的 Agent。

### 10.2 点名单个或多个 Agent

点击输入框上方的 Agent 名称，或输入完整 `@Agent 名称`。可以一次点名多个 Agent，它们会并行执行；同一个 Agent 自己的多个任务按顺序执行。

点击“全体”，或以“大家 / 每个人 / 所有人 / @全体”开头，可让当前群中所有有权限且非静默 Agent 分别响应。

### 10.3 创建任务

点击输入框下方 **创建任务**，填写：

- 标题；
- 目标 Agent；
- 具体要求；
- 验收标准（可选）；
- 所属项目步骤（可选）；
- 执行依据（选择步骤后出现）。

任务比普通 @ 更适合需要跟踪、验收、提交目录或进入看板的工作。

任务运行时间较长时，发送按钮会变成红色停止按钮；也可在原话题点击 **停止本次委托**。停止会取消这次根任务及其尚未完成的后续 Agent 接力，不影响已经交付的历史内容。

### 10.4 附件

点击 **附件**，最多同时发送 5 个文件，单文件不超过 50 MB。支持 PDF、Word、Excel、CSV、TXT、Markdown、PPT 和常见图片，不接收可执行文件或脚本。

附件与消息绑定后，目标 Agent 所在 Client 会下载并校验，再把本地路径交给真实 CLI。

### 10.5 话题回复

每条真人任务及其 Agent 回复默认组成一个可折叠话题。点击“回复话题”继续同一件事；不要另发一条无关联消息，否则看板和验收链会被拆开。

### 10.6 Agent 接力

Agent 在回复中单独一行写 `@完整显示名`，平台可创建父子任务让另一 Agent 接手，并把结果回送给委派 Agent。平台限制接力深度和总任务量，避免无限互相点名。

### 10.7 Brainstorm 专题讨论

1. 先把一个 Agent 设为“主协调 / 自动分诊”。
2. 输入 `/brainstorm 议题内容`。
3. 主协调开题，其他非静默 Agent 独立分析。
4. 全部回传后，主协调自动总结。

Brainstorm 是一次专题会议，不会把 Agent 永久改成自动回复，也不会自动把讨论结果变成执行任务。

## 11. 会话命令

点击输入框下方 **命令** 选择，或直接输入：

- `/new [主题]`：在当前群聊开启新的会话段。
- `/clear`：清理当前视图，并从此处切断后续 Agent 上下文；旧消息保留用于审计。
- `/restart`：归档当前上下文并重新开始，同时清除该群原生 Agent session。
- `/reset`：`/restart` 的兼容别名。
- `/brainstorm [议题]`：发起一次主协调组织的专题讨论。

`/clear`、`/restart` 和 `/reset` 后，旧消息不会再进入后续 Agent 上下文。

## 12. 五个群聊项目视图

每个群聊顶部有五个视图：

### 总览

给领导或项目管理员看整体情况：总体进度、进行中事项、待验收、风险与等待、负责人及 Git 主仓地址。

### 聊天

真人与 Agent 的日常时间线。普通聊天不计入项目进度；选择项目步骤的会话会成为看板事项。

### 看板

设置项目目标、步骤、子步骤、权重、负责人、状态、本机工作目录和审查流程。

### 知识库

存放要长期反复参考的规范、历史材料和样例：

- “工作区共享”可供同一工作区各群引用；
- “本群资料”只供当前群使用。

Agent 领取本群任务时会自动取得两层知识库文件。知识库不是开发目录，也不会代替 Git 正式版本。

### 产物

集中查看 Agent 的待验收或已完成交付，以及会话中的阶段文件。长期参考材料仍应放知识库。

## 13. 建立项目计划和计算进度

1. 进入群聊 → **看板**。
2. 点击 **编辑计划**。
3. 填写总目标。
4. 新建主要步骤；需要时选择父步骤创建子步骤。
5. 为同层步骤填写权重值。
   - 新增或修改时查看输入区下方的实时权重账本：它会显示当前同层合计、填写后合计、预计占比，以及距离 100 还差多少或已经超出多少。
   - 建议每一层合计填写为 100，最容易理解；不等于 100 时系统仍会按比例折算。
6. 随时点击铅笔修改步骤名称、层级、权重和负责人；无需删除重建。
7. 负责人可选择真人，也可选择群内 Agent，并可随时增删。
8. 将步骤状态设为：待开始、进行中、待验收、已完成或已作废。

看板中的百分数是**进度**，不是权重。权重值会在文字中单独显示。

进度规则：

- 只有“已完成”的叶子步骤贡献 100%。
- 待开始、进行中、待验收都不提前计入。
- 有子步骤时，父步骤由有效子步骤按权重汇总。
- 已作废步骤退出分母。
- 聊天数、Agent 回复数、修 Bug 次数和提交次数都不会自动增加进度。

## 14. 三种项目资料来源

群聊成员对群内共享资料采用统一只读权限，不再按项目角色限制读取。发送一个已关联步骤的会话或任务时，只需明确使用哪一份项目内容：

### 公共底稿（默认）

读取 Server 上该步骤当前统一版本的固定快照。所有工作区成员均可下载；群内 Agent 执行时取得任务临时副本。临时副本中的修改不会回写或覆盖公共底稿，仍需负责人提交和管理员验收。

### 负责人本机最新进展（不提交）

任务直接在被点名 Agent 所在电脑的已绑定目录中运行，适合问“B 现在做到哪里了”。不会先下载公共目录，不会自动上传、提交或合并。

使用条件：

1. 该真人和该 Agent都已被设为步骤负责人；
2. 负责人在自己的 Client 绑定了这个步骤的本机目录；
3. 被点名的是该负责人的 Agent；
4. 对方 Client 在线，或任务等待其上线。

### 不读取文件

只保留事项和步骤归属，本次任务不读取代码或项目文件。适合纯知识问答、会议纪要和计划讨论。

## 15. 本机目录、步骤底稿和 Git 正式版本

这三者是同一项目流程的不同阶段。

### 15.1 绑定本机实时工作目录

负责人在看板步骤的“我的本机目录”区点击 **绑定目录**，选择自己持续工作的原目录。

- 不上传文件；
- 不移动原目录；
- 绝对路径只保留在该 Client；
- 之后群里可以点名该负责人的 Agent 原地查询最新进展；
- 可“打开”“更换”或“解除”。

更换负责人后，已有 Server 版本和会话上下文仍在；新负责人需要在自己的 Client 重新绑定自己的本机目录。

### 15.2 上传步骤底稿

看板步骤“公共底稿”中的 **上传底稿 / 更新底稿** 会把选定目录复制一份到 Server，成为该步骤共享版本。原目录不会被移动或修改。

- 所有工作区成员都能下载和读取；
- 只有项目管理员或该步骤负责人能上传、更新或解除；
- 群内 Agent取得的是冻结的任务临时副本，不能直接修改 Server 公共底稿；
- 每次更新都会保留 Git 版本历史。

上传后可以：

- 所有成员下载 Server 上的公共底稿；
- 负责人或管理员更新公共底稿；
- 点击“解除”取消当前步骤绑定。解除不会删除历史版本，也不会删除本机原目录。

它适合首次建立团队共同起点，不等于审查合并。

### 15.3 Git 主仓

每个工作区在 Server 有一个受保护的 Git 主仓，`main` 是团队正式版本。

普通成员不需要手写 Git 命令。界面中的“提交审查 → AI 审查 → 管理员合并 → 合并后校验”就是 Git 分支、PR 和合并流程的图形化表达。

高级用户可以从“总览”复制 Git 地址，用标准 Git 客户端操作同一主仓；图形流程和命令行共用一份仓库，不是两套版本。

## 16. 从工作到提交、审查和验收

### 16.1 建立任务

1. 管理员在看板建步骤并指定真人、Agent 负责人。
2. 负责人绑定自己的本机目录。
3. 在聊天或“创建任务”中选择项目步骤和执行依据。
4. Agent 在原话题交付文字或文件。

### 16.2 纯文字或附件交付

Agent 成功交付后，事项进入“待验收”。

操作位置：

- 原话题中出现“文字与文件交付待你验收”；或
- 看板事项中出现“文字与文件交付待验收”。

管理员查看完整答复和附件后点击：

- **验收通过**：事项完成；
- **退回修改**：回到进行中。

### 16.3 目录或代码交付

负责人在对应任务话题点击 **选择目录并提交审查**。平台会：

1. 保存这次目录快照；
2. 创建独立任务分支；
3. 将事项转为待验收；
4. 保持 `main` 不变。

需要补充修改时，点击 **更新任务工作区** 后重新提交。

### 16.4 AI 审查与合并

1. 进入 **看板**，展开对应待验收事项。
2. 选择“主审 Agent”。
3. 选择“合并后校验 Agent”。
4. 点击 **发起 AI 审查**。
5. 主审 Agent 在固定候选分支副本中检查文件、差异和测试，并返回通俗结论。
6. AI 建议通过后，管理员点击 **按 AI 建议合并**。
7. Server 将候选分支合入受保护的 `main`。
8. 校验 Agent 自动基于合并后的正式版本再次验证。

AI 建议修改时点击 **退回修改**。真人管理员保留最终决定权；Agent 负责解释、检查和验证，不能自行绕过管理员合并。

合并只完成当前事项。对应项目步骤仍需管理员将状态设为“已完成”，才按权重进入总体进度。

## 17. 如何让别人的 Agent 汇报本机最新进展

假设步骤由成员 B 和 B 的 Codex 负责：

1. 管理员先在看板把 B 和“B Codex”设为该步骤负责人。
2. B 在自己的 Client 打开该步骤，点击“绑定这台电脑的目录”。
3. B 的 Agent 主人将该 Agent 设为“工作区可见、所在群成员调用”，并共享本次需要的 Skill。
4. 你在群里创建任务，选择该步骤。
5. 执行依据选择“负责人本机最新进展（不提交）”。
6. 点名 B Codex，要求汇报当前进展、改动、阻塞和下一步。

任务会在 B 的原目录执行。它不会先下载 Server 公共目录，也不会把未完成工作自动上传。只有 B 明确“选择目录并提交审查”时，最新成果才进入团队候选版本。

## 18. 上下文共享规则

- 同一群聊的真人看到同一条群聊时间线、话题、任务和交付。
- Agent 执行时获得当前有效会话窗口中的最近群聊上下文，以及当前话题、附件、相关知识库和明确选择的项目目录来源。
- 每个 Agent 的原生 session 独立保存；不是把所有 Agent 强制放进同一个厂商会话。
- 工作区其他群聊的全部聊天不会默认无条件注入当前任务。
- 工作区知识库可跨同一工作区群聊共享；本群资料只属于当前群。
- `/clear`、`/restart`、`/reset` 会切断后续 Agent 上下文，但历史消息仍可审计。

## 19. 在线、消息同步和自动重连

### 顶部“消息实时同步 / 消息自动同步”

这是**群聊消息通道**，不是 Agent 在线状态：

- 消息实时同步：WebSocket 正常，新消息实时到达。
- 消息自动同步（旧版称轮询同步）：WebSocket 暂不可用，但页面仍定时补齐消息，属于可用的降级模式。

### Agent 状态

- **就绪**：Client 已连接，可以接任务。
- **待执行**：已有任务排队。
- **执行中**：真实本机 Agent 正在运行。
- **等待上线**：任务已保留，但目标 Client 暂未连接。
- **不可用**：Client 在线，但本机找不到可执行 CLI 或配置异常。

Client 运行时会自动重连。离开办公网时显示离线；回到团队局域网后会基于稳定团队身份、候选地址和局域网发现恢复，不需要重新邀请、注册账号或配对设备。

需要人工检查时：右侧 **高级 · 连接诊断 → 运行检查**。若本机离线，打开 Client 或在“添加我的 Agent”中点 **重新连接并查找**。

## 20. 如何证明调用的是真实 Agent

展开 Agent 交付下方的 **查看执行凭证**，核对：

- Agent 类型；
- 真实 CLI 绝对路径和版本；
- 执行设备名；
- 进程 PID；
- 开始与结束时间；
- 原生 session ID；
- 命中的 Skill、知识库或资源名称。

“独立 Agent 身份 + 真实可执行文件/PID + 原生 session”共同构成真实性证据。Codex、WorkBuddy、Claude Code 等厂商桌面软件是否显示无头 CLI 任务，由各厂商自己的历史同步机制决定，不能作为唯一标准。

常见认证注意：WorkBuddy 桌面 App 保持登录，不等于它的内置 CLI 一定已登录。若交付显示 `Authentication required. Please use /login`，需要在该电脑上为 WorkBuddy/CodeBuddy CLI 单独完成登录。

## 21. 更新、备份和迁移

### Client 更新

1. 从 Server 下载中心下载同主版本最新版。
2. 正常退出旧 Client。
3. 覆盖安装并重新打开。
4. 登录和设备身份会在同一主版本内保留，不应重新邀请或配对。

### Server 更新

1. 先退出 Server。
2. 备份 Server 设置中显示的权威数据目录。
3. 覆盖安装同主版本 Server。
4. 重新打开，核对团队身份、地址、账号、工作区和群聊。

### 大版本升级

大版本使用独立应用标识和数据目录。应完整从头验收，不允许旧登录、旧 Runner 或旧数据静默混入。旧版先归档，再安装新 Server 和 Client；只有明确选择时才导入历史。

### 迁移到局域网固定电脑

迁移的核心是 Server 权威数据目录，而不是复制每个人的 Client：

1. 停止旧 Server。
2. 完整复制权威数据目录到新主机。
3. 在新主机安装同版本 Server，并指向该目录。
4. 保持同一团队身份，设置新主地址或 DNS。
5. 启动后验证账号、工作区、群聊、Git、附件和下载中心。
6. 各 Client 会寻找同一团队的新入口；必要时重新登录，但不重新创建账号或 Agent。

## 22. 常见问题速查

| 现象 | 原因与处理 |
| --- | --- |
| Client 打开空白 | 旧地址已失效、Server 未启动或网络不在同一局域网。先打开 Server，确认当前团队地址，再重启 Client；不要继续使用旧书签地址。 |
| 登录页再次出现 | Server 地址来源变化后浏览器会话可能不共享。用原账号重新登录，不要重新注册。 |
| 扫描显示未找到 | 纯网页不能扫描；确认 Client 本机连接、CLI 已安装并已认证，再“重新连接并查找”。 |
| Agent 一直离线 | 目标电脑 Client 未运行或无法访问 Server。让设备所有者打开 Client；任务可继续等待上线。 |
| `Runner does not have the target Agent configuration` | 群中仍引用旧/重复 Agent 记录，或当前 Client 未加载该配置。让主人重新连接、扫描并复用当前 Agent，必要时把旧记录移出群。 |
| WorkBuddy 报 Authentication required | WorkBuddy 内置 CLI 未登录；在目标电脑完成 CLI `/login`，桌面 App 登录不能替代。 |
| @ 多个 Agent 只有一个回复 | 检查其他 Agent 的在线状态、调用权限、响应模式和任务进度；明确 @ 的任务不依赖“回复所有真人消息”。 |
| 点别人的 Agent `+` 无效 | 对方主人尚未开放“工作区可见 / 所在群成员调用”，或 Agent 离线不可用。先由主人设置权限。 |
| 本机最新目录不能用 | 真人、Agent、步骤负责人或本机目录绑定缺一项；必须点名同一负责人账号拥有的 Agent。 |
| 只有文字回复，没有验收按钮 | 会话必须关联项目步骤并形成任务事项。到原话题或看板查看“文字与文件交付待验收”。 |
| 有目录交付但不能合并 | 先在原话题“选择目录并提交审查”，再到看板发起 AI 审查；AI 通过后管理员才能合并。 |
| 顶部显示轮询同步 | 仅表示消息采用定时同步，仍可正常聊天；Agent 在线另看成员卡片。 |
| Server 关窗后仍在运行 | 它缩到菜单栏后台。要停止服务，从菜单栏 AgentCollab Server 图标选择“退出”。 |

## 23. 推荐的四种使用模板

### 日常群聊

- Agent 默认“仅被 @”。
- 普通内容真人聊天。
- 需要执行时点名一个或多个 Agent。

### 固定主协调

- 设一个主协调 Agent。
- 真人直接描述目标。
- 协调 Agent 拆分、点名专家并汇总。

### 专题头脑风暴

- 群内保留一个主协调。
- 使用 `/brainstorm 议题`。
- 只形成讨论结论；要落地时另建结构化任务。

### 正式项目协作

- 工作区代表完整项目，群聊代表协作频道。
- 看板先建步骤、权重和负责人。
- 问最新进展选择“负责人本机最新进展”。
- 统一分析选择“团队正式版”。
- 完成后提交审查，AI 检查，管理员合并，另一 Agent 校验。
