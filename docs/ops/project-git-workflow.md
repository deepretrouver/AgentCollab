# 工作区项目计划与 Git 协作

AgentCollab 将项目管理和日常群聊分开：普通消息只保留在聊天时间线中；只有明确选择项目步骤的会话或任务，才成为看板 Issue 并进入项目统计。

## 对应关系

- 工作区：一个完整项目。Server 在后台保存受保护的 Git 主仓，但不强迫所有人每次汇报前下载它。
- 项目步骤：主要阶段；可继续创建带独立权重的子步骤。
- 群聊：围绕某个步骤或跨步骤开展协作。管理员可设置群聊默认步骤。
- 负责人本机目录：负责人在自己的 Client 为某一步骤选择的持续工作现场。绝对路径只保存在该电脑。
- 公共底稿：Server 上可供全体成员统一读取的版本。只有项目管理员或步骤负责人可以更新。
- 话题会话 / 任务：选择步骤后成为 Issue；执行前只需选择公共底稿、负责人本机最新进展，或不读取文件。
- 待验收：相当于 PR 等待审查。
- 审查并合并：由工作区 Owner 或管理员将已推送分支合入受保护的 `main`，同时验收该 Issue。

## 使用顺序

1. 在群聊“看板”中填写项目目标，建立主要步骤、子步骤及权重。
2. 可在群详情设置当前群聊的默认步骤；也可保持“不固定”。
3. 发送消息或创建 Agent 任务前，在输入框上方选择归属步骤。若选择“普通会话”，该消息不计入项目。
4. 管理员为步骤指定真人和 Agent 负责人。负责人在自己的 Client 点击“绑定这台电脑的目录”；这不会上传文件，Server 只记录目录名称、负责人和设备状态。
5. 想问尚未提交的最新进展时，在会话中选择该步骤和“负责人本机最新进展”，再点名该负责人的 Agent。任务会在那台电脑的原目录中运行，不会先下载公共目录，也不会自动提交或合并。
6. 想让所有 Agent 根据同一版本分析时，选择“公共底稿”。Client 会取得 Server 上的任务临时副本，不受负责人本机未提交修改影响，也不会直接覆盖 Server 公共底稿。
7. 负责人做完后，在对应任务会话提交目录审查。平台自动创建事项分支、保存此次目录快照并进入待验收；这是本机最新进展转成团队候选版本的明确节点。
8. Owner 或管理员在看板指定本群的“主审 Agent”和“合并后校验 Agent”，点击“发起 AI 审查”。主审 Agent 会收到待合并分支的固定副本，实际检查文件和测试，并输出面向真人的结论。
9. AI 建议合并后，管理员点击“按 AI 建议合并”；Server 才执行受保护的合并。AI 建议修改时，管理员点击“退回修改”。原始文件清单和增删行数默认收在“技术详情”。
10. 合并后，公共底稿更新到新的 `main`；校验 Agent 自动取得新版本再次验证。只有校验通过，事项才进入“已完成”。
11. 合并只完成对应 Issue。项目总进度仍由管理员验收项目步骤后，按步骤权重计算。

## 普通成员只需理解四个动作

- **读取公共底稿**：所有工作区成员和群内 Agent均可读取，聊天任务只能使用临时副本。
- **绑定本机目录**：不上传，只让负责人自己的 Agent 能在原工作现场查询最新进展。
- **提交审查**：把负责人当前成果转成独立候选版本，等待审查，尚不覆盖团队正式版。
- **确认合并**：审查通过后才更新团队正式版；其他成员下一次选择“团队正式版”时取得新版本。

Git 地址、commit 和分支只用于后台版本保护、审查和高级操作，不是普通成员接入 Agent 的前置要求。

高级用户仍可从“总览”取得 Git 地址，使用标准 Git 客户端操作同一个仓库。图形流程和命令行流程共享同一份主仓，不是两套数据。

## 进度规则

- 顶层步骤按各自权重计算总体进度。
- 有子步骤时，父步骤进度由有效子步骤按权重计算。
- 只有状态为“已完成”的叶子步骤贡献 100%；待开始、进行中、待验收均不提前贡献进度。
- 已作废步骤退出分母。
- 消息数、Agent 回复数、修复次数和代码提交次数不会自动增加项目进度。

## 局域网安全边界

Git Smart HTTP 使用 AgentCollab 账号认证，并校验工作区成员身份。HTTP 会暴露 Basic Auth 凭据给局域网链路，因此正式办公部署应在 Server 前启用 HTTPS；未启用前只适合受信任的隔离网段。
